# Learning log

Notes for an experienced React/TypeScript developer who is new to React Native and Expo. Each entry
says how something differs from React on the web and where to see it in this repo.

### What is different from React on the web

**No HTML, no CSS files.** You render `<View>` (a div), `<Text>` (the only thing that can hold text),
`<Pressable>` (a button), `<ScrollView>` and `<TextInput>`. Styles are JavaScript objects made with
`StyleSheet.create`. There is no cascade: a style applies to the component you give it and nothing
else. The one exception is text nested in text, which inherits like a `<span>`
([AppText.tsx](packages/ui/src/components/AppText.tsx)).

**Flexbox is the only layout, and its defaults differ.** `flexDirection` defaults to `'column'`, not
row. Every view is `display: flex` and `position: relative` already. There is no CSS grid; the bottom
navigation's three equal columns are `flex: 1` children
([BottomNav.tsx](packages/ui/src/components/BottomNav.tsx)).

**Units are density-independent points.** `width: 96` means 96 points, which is 96 CSS px in the
design, and 288 physical pixels on a 3x screen. That is why a 1170 x 2532 emulator at 480 dpi shows
the 390 x 844 design frame exactly.

**Nothing scrolls unless you say so.** Content that overflows a `View` is just cut off. Wrap it in a
`ScrollView`, or a list component for long lists.

**Nothing reacts to touch unless you say so.** There is no `:hover` or `:active`.
[Tappable.tsx](packages/ui/src/components/Tappable.tsx) gives every control the same pressed state.

**Safe areas.** The app draws behind the status bar and the system navigation bar. `useSafeAreaInsets()`
tells you how tall they are, and you add that to your padding
([HomeScreen.tsx](apps/customer/src/features/home/screens/HomeScreen.tsx)).

**Text needs help.** One `<Text>` has one font, with no fallback list like CSS `font-family`. Tamil
characters are split into their own runs ([splitByScript.ts](packages/ui/src/text/splitByScript.ts)).
`lineHeight` is an absolute number, not a multiplier. Android adds padding above and below text unless
you set `includeFontPadding: false`.

**Gradients and shadows are not CSS strings.** A gradient is a component
([Gradient.tsx](packages/ui/src/components/Gradient.tsx)); a shadow is the `boxShadow` style, which the
New Architecture supports with the same numbers as CSS.

### Expo and the native side

**Expo Go versus a development build.** Expo Go is a ready-made app that can only run JavaScript using
the native modules it already contains. A development build is your own app, compiled with exactly the
native modules you need. We use development builds because ringing alerts need native code.

**Two kinds of change.** JavaScript changes reload instantly from Metro (the bundler, like Vite's dev
server). Native changes (adding a library with native code, changing `app.config.ts`, fonts, icons)
need a rebuild with `pnpm android`.

**Continuous Native Generation.** The `android/` folder is generated by `expo prebuild` from
`app.config.ts` and is not committed. You never edit it; you change the config or write a config
plugin.

**Config plugins.** A plugin edits the native project during prebuild. `expo-font`'s plugin copies our
fonts into the Android project so they exist before the first frame
([fonts.config.js](packages/ui/fonts.config.js)).

**Expo Router.** Files in `src/app` are routes, like Next.js. `_layout.tsx` wraps them. Route files
stay thin and render a screen from `src/features`.

### Animation

**Two JavaScript threads.** React runs on the JS thread. Reanimated runs animation code on the UI
thread so animations stay smooth while React is busy. A _shared value_ lives on the UI thread; changing
it does not re-render React. A function marked `'worklet'` is copied to the UI thread
([splashTimeline.ts](apps/customer/src/features/start/splashTimeline.ts)).

**Skia.** A 2D drawing canvas for things views cannot do: gradient-filled text, blur, stretching glyphs
([SplashCanvas.tsx](apps/customer/src/features/start/components/SplashCanvas.tsx)). It reads Reanimated
shared values directly.

**One clock.** The opening animation drives every element from a single 0 to 1 progress value through
pure functions, so any frame can be reproduced and tested without a device.

### Testing

- Pure functions: plain Jest ([gradient.test.ts](packages/ui/src/theme/gradient.test.ts)).
- Components and screens: React Native Testing Library. In version 14 both `render` and `fireEvent` are
  async, so they need `await`.
- Reanimated in Jest needs its resolver ([jest.config.js](apps/customer/jest.config.js)). Skia needs a
  GPU, so the splash canvas is replaced by a stub in tests
  ([jest.setup.ts](apps/customer/jest.setup.ts)).
- Visual check: `pnpm visual` screenshots the emulator and compares with `design/screenshots`.

### Lessons from the Windows build

Three separate failures, all recorded in
