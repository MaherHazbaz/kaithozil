# 0001: React Native with Expo, in a pnpm + Turborepo monorepo

Date: 2026-11-11. Status: accepted.

## Decision

Kaithozhil is built with Expo SDK 58 (React Native 0.88, New Architecture, Hermes) and TypeScript in
strict mode, replacing the earlier Flutter plan. The repository is a pnpm workspace run by Turborepo:
`apps/customer`, later `apps/worker` and `apps/admin`, with `packages/ui` and `packages/core` shared.

## Why

- The owner is an experienced React/TypeScript developer; the admin panel (Next.js) and Supabase Edge
  Functions are TypeScript too, so types and zod schemas are shared end to end.
- Development builds rather than Expo Go, because worker ringing alerts need native modules
  (Notifee, foreground service) that Expo Go cannot load.
- Continuous Native Generation: `android/` is generated by `expo prebuild` from `app.config.ts` and is
  not committed. Native changes are made through config plugins, never by editing `android/`.

## Consequences

- The old Flutter starter is kept in `archive/flutter/` for reference only.
- `app.config.ts` defines three variants (`APP_VARIANT` = development, preview, production) with
  separate package ids, so builds can be installed side by side.
- React Compiler is enabled (Expo's template default), so components are memoised automatically.
  Reanimated shared values are written with `.set()` in React code to stay compatible with it.
